## 1. 角色与权限边界

角色必须"能做的事确实不同"，这是选题规则第 22 条的硬要求，也是 RBAC 15 分的基础。

| 角色 | code | 核心职责 | 一句话区分 |
|---|---|---|---|
| 普通用户 | `USER` | 写 / 改 / 删自己的日记，申请公开，评论、点赞、举报他人公开内容，用 AI 处理自己的日记 | 只能碰自己的数据 |
| 内容审核员 | `REVIEWER` | 审核公开申请（通过 / 驳回），处理举报单，下架违规内容 | 只能审核，不能管人 |
| 运营 | `OPERATOR` | 标签库维护、公告发布、精选推荐、平台数据看板 | 只管内容和运营数据 |
| 超级管理员 | `ADMIN` | 用户管理（增删改查、禁用/启用、分配角色）、角色管理（分配权限）、全量数据、系统配置 | 只管人和权限，不审内容 |

> 设计要点：把「审内容」和「管人」拆开给两个角色，权限矩阵立刻有形状，答辩时一句话能讲清边界。

## 3. 架构设计（附加分「架构升级 +2」的核心）

不使用微服务，走 **DDD 四层 + 领域模型**。零额外开发成本，但从第一天就必须按这个包结构落盘，后期改不动。

```
浏览器 ─HTTP/WS─> Vue3 SPA ─> Controller(interfaces)
                                    │ DTO
                                    ▼
                            Application Service（用例编排 / 事务边界）
                                    │ Command / Query
                                    ▼
        Domain（聚合根 Diary、状态机、领域服务、仓储接口）
                                    │ 仓储接口
                                    ▼
        Infrastructure（MyBatis-Plus 实现 / Redis / WebSocket / AI Client）
                                    │
                          MySQL 8  ──  Redis 7  ──  DeepSeek API
```

**分层职责与评分点对应：**

| 层 | 放什么 | 禁止什么 |
|---|---|---|
| `interfaces` | `controller`、`dto`（请求/响应）、`assembler`（DTO↔领域对象）、`GlobalExceptionHandler` | 禁止出现业务判断、禁止返回实体 |
| `application` | `service`（用例编排）、`command` / `query` 对象、`event` 发布 | 禁止直接写 SQL、禁止出现 HTTP 类型 |
| `domain` | `model`（聚合根/实体/值对象）、`repository` 接口、`statemachine`、`service`（领域服务） | 禁止依赖 Spring 注解以外的框架、禁止依赖 infrastructure |
| `infrastructure` | `persistence`（PO + Mapper + RepositoryImpl）、`security`、`cache`、`websocket`、`ai`、`config` | — |

**包结构（直接照建）：**

```
com.daytrace
├── DiaryApplication.java
├── interfaces
│   ├── controller      AuthController / UserController / RoleController
│   │                   DiaryController / TagController / ReportController
│   │                   AnnouncementController / AiController / StatsController
│   ├── dto             按模块分子包：auth / user / role / diary / tag / report / ai
│   ├── assembler
│   └── advice          GlobalExceptionHandler / ResultResponseAdvice
├── application
│   ├── service         AuthAppService / UserAppService / DiaryAppService
│   │                   ReviewAppService / ReportAppService / AiAppService
│   ├── command
│   ├── query
│   └── event           DiaryPublishedEvent / ReportHandledEvent
├── domain
│   ├── model
│   │   ├── user        User / Role / Permission（聚合根）
│   │   ├── diary       Diary（聚合根）/ DiaryStatus / DiaryAuditRecord
│   │   ├── tag         Tag
│   │   ├── report      Report / ReportStatus
│   │   └── announcement
│   ├── repository      每个聚合一个接口
│   ├── statemachine    DiaryStateMachine / ReportStateMachine
│   └── service         DiaryDomainService（归属校验、状态校验）
└── infrastructure
    ├── persistence
    │   ├── po          UserPO / DiaryPO ...（对应表）
    │   ├── mapper      *Mapper（MyBatis-Plus）
    │   └── repository  *RepositoryImpl
    ├── security        JwtTokenProvider / JwtAuthenticationFilter
    │                   PermissionEvaluator / LoginFailureHandler
    ├── cache           TokenBlacklistService / DiaryCacheService / RateLimitService
    ├── websocket       NotifyWebSocketHandler / WsAuthInterceptor
    ├── ai              AiClient（接口）/ DeepSeekClient（实现）/ PromptTemplates
    └── config          SecurityConfig / MybatisPlusConfig / RedisConfig / OpenApiConfig
```

**一次请求的鉴权链路**（README 第 3 章要这张时序图，用 mermaid 画）：
```
登录 → 签发 JWT(jti + sub + tokenVersion) → 前端存 token
请求 → JwtAuthenticationFilter
      ├─ 解析签名/过期
      ├─ 查 Redis 黑名单 jti？命中 → 401
      ├─ 比对 DB tokenVersion？不一致 → 401（改密/禁用即全局失效）
      └─ 装载 authorities → @PreAuthorize 校验 → 403 / 放行
退出 → jti 写 Redis（TTL = 剩余有效期）→ 旧 token 立即 401
```

## 6. 状态机设计（「状态流转 4 分」的核心）

### 6.1 日记发布流（主流程）

```
                    ┌──────────── submit(author) ────────────┐
                    │                                        ▼
   DRAFT ───────────┘                                    PENDING
     ▲                                                       │
     │ undo(author)                                          ├─ approve(reviewer) ─> PUBLISHED ──┐
     │                                                       │                         │          │
     └──────────── reject(reviewer, reason) ─── REJECTED ◄───┘                         │          │
                                                    │                                   │          │
                                  resubmit(author)  │                    takedown(reviewer/admin)
                                                    ▼                                   │          ▼
                                                 PENDING                                ▼      TAKEN_DOWN
                                                                                   PRIVATE ◄──┘
                                                                              (author unpublish)
```

**允许的跳转（后端 `DiaryStateMachine` 硬编码白名单，其余一律 409/400）：**

| From | Action | To | 允许角色 |
|---|---|---|---|
| DRAFT | submit | PENDING | 作者本人 |
| PENDING | approve | PUBLISHED | REVIEWER |
| PENDING | reject | REJECTED | REVIEWER |
| PENDING | withdraw | DRAFT | 作者本人 |
| REJECTED | resubmit | PENDING | 作者本人 |
| PUBLISHED | unpublish | PRIVATE | 作者本人 |
| PUBLISHED | takedown | TAKEN_DOWN | REVIEWER / ADMIN |

非法跳转示例（演示时必演）：对 `DRAFT` 直接调 `approve` → **409**，`{"code":40901,"message":"当前状态不允许审核"}`。

### 6.2 举报处理流（副流程，不同角色不同步骤）

```
PENDING ──accept(reviewer)──> ACCEPTED  ──联动：日记自动 TAKEN_DOWN + 通知作者
        └─reject(reviewer)──> REJECTED  ──通知举报人
```

两条流各自有角色分工、各自有非法跳转校验，超额满足"至少 1 个有状态流转的流程"。

### AI `/api/ai`
| 方法 | 路径 | 权限 | 说明 |
|---|---|---|---|
| POST | `/diaries/{id}/summary` | 归属校验 | 生成 ≤100 字摘要，写回 diary.summary |
| POST | `/diaries/{id}/tags` | 归属校验 | 推荐 3 个标签（不自动落库，前端确认） |
| GET | `/report/monthly` | 登录 | 自己当月情绪报告（聚合 mood 字段） |

> 加分项原文要求"AI 调用必须经过后端，且遵守权限" —— 所有 AI 接口先做归属校验再调模型，`ai_call_log` 留痕，Redis 限流（每用户每天 20 次）。

### 统一返回格式
```json
{ "code": 0, "message": "ok", "data": {...}, "traceId": "..." }
```
错误码分段：`401xx` 认证、`403xx` 权限、`409xx` 状态非法、`400xx` 参数校验。全局异常处理器兜住所有异常，**绝不把堆栈返回前端**。

## 8. 附加分作战表（最高 +10，本方案 7.5~9）

| 附加项 | 分值 | 我们的做法 | 额外成本 | 优先级 |
|---|---|---|---|---|

## 11. 演示脚本（5 分钟，逐条对上评分点）

1. **注册**：故意输 `abc123` 短密码 → 后端返回参数错误（证明后端校验）；注册成功 → 默认 USER 角色
2. **登录**：错密码 → "用户名或密码错误"（不泄露具体原因）；成功拿 token
3. **写日记 → 提交审核**：`DRAFT → PENDING`
4. **切审核员账号**：审核列表看到待审 → 通过 → **作者端 WebSocket 实时弹出"审核通过"通知**（不刷新页面）
5. **越权演示**：USER 用 bob 的 token 改 alice 的日记 ID → **403**；Postman 直接调 `PUT /api/users/1/status` → **403**（老师一定会这么验）
6. **非法状态跳转**：对 `DRAFT` 直接调 approve → **409**
7. **AI**：给自己日记生成摘要 + 情绪标签；对别人日记调 AI → 403
8. **退出登录**：退出后用旧 token 调 `/api/auth/me` → **401**（4 分关键）
9. **管理员禁用账号**：alice 被禁用后，其现有 token 立即 401（tokenVersion 机制）
10. **跑测试**：`mvn test` + 打开 JaCoCo 报告（覆盖率高亮 Service 层）
